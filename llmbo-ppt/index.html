Section 1 · What we're trying to design

A charging protocol is a sequence of three currents — and three conflicts at once.

We optimize a multistage constant-current (MCC) protocol with K = 3 stages: each stage carries a current Ik and a delivered SOC span Δsk. The simulator evaluates the full charge cycle — coupled electrochemistry, thermal, and a degradation proxy — and returns a 3-vector.

min · tc
Objective 1
Charging time
tc · seconds

Higher currents shorten the charge, but each amp also drags heat and side-reaction severity with it. The fastest protocol is rarely the durable one.

min · ΔTp
Objective 2
Peak temperature rise
ΔTp · K

The cell is constrained to T ≤ 328.15 K. A protocol that exceeds it during the cycle is not merely suboptimal — it is infeasible and removed from the archive.

min · Dchg
Objective 3
Degradation proxy
Dchg · a.u.

A trajectory-averaged control-oriented indicator of side-reaction severity — not a long-cycle fade endpoint, but one that the optimizer can read every evaluation.

Constraints: Imin ≤ I(t) ≤ Imax, V(t) ≤ Vmax, T(t) ≤ Tmax on the full time horizon. Path-dependent feasibility is checked by the simulator, not by the optimizer.

Section 2 · The computational bottleneck

One evaluation is a coupled PDE solve. The whole budget is 56 of them.

Each call is expensive.

A single protocol evaluation runs an SPMe-based electrochemical model coupled to a thermal model, then accumulates the degradation proxy along the time trajectory. A typical cycle costs seconds-to-minutes on a workstation — small per call, huge at 56 calls per seed across five seeds across two batteries.

The surrogate changes the game.

Gaussian-process BO and decomposition-based MOBO can find a good Pareto set with few evaluations because the GP prioritizes where the next call is informative, not where the search is convenient. ParEGO, in particular, sweeps trade-off directions through a Tchebycheff scalarization.

Where MOBO still hurts With only a handful of evaluated points, the surrogate is sensitive to the initial design. The first six calls may already decide whether the optimizer sees a useful trade-off front at evaluation 30 — or wastes the early budget on regions that never recover.
The opening-move problem The MOBO community has refined search strategy and acquisition design in many directions, but how to seed the database with protocol-domain-valid, decision-space-diverse points — without running a separate warm-start optimizer — has been an open question.

Section 3 · The move that makes this paper

An LLM knows what a battery engineer knows — and we can ask it before the surrogate has anything to say.

Battery knowledge is partly numerical (models, archives) and partly qualitative (typical multistage current patterns, SOC allocation heuristics, current-monotonicity rules). MOBO uses the first kind well. The second kind has been hard to feed in without a custom surrogate or a domain-specific warm-start. LLMs sit on that qualitative side naturally.

A · what LLM is good at
Qualitative

Domain text → numerical candidates

  • Multistage current patterns: high → medium → low
  • SOC allocation heuristics across the cycle
  • Thermal–degradation trade-off priors
  • Heuristic ranking of "reasonable" schedules
B · what LLM is not used for
Numerical

Objective values, feasibility, GP training

  • No LLM proposal enters D as an unevaluated target
  • No LLM output modifies the GP posterior
  • No LLM prediction replaces a simulator call
  • No LLM region restricts the feasible search space

Boundary: the LLM is a candidate generator and a regional restart source — not a surrogate, not a feasibility oracle, not a ground-truth labeler.

Section 5 · Mechanism 1 of 2

LLM-informed initialization: domain text → admissible, diverse first six points.

We ask the LLM for a pool of numerical protocol candidates plus a heuristic score. We then screen for admissibility, repair, rank by a soft penalty on the terminal SOC span, prefer nonincreasing current sequences, and pull a portfolio that maximizes a score-softpenalty-monotonicity-diversity objective. The rest of the six-eval budget is filled with random protocol-domain-valid points. Every selected θ is evaluated by 𝒮 before joining 𝒟.

Selection score (Eq. 7)

# h_ws: LLM heuristic in [0,1] # p_soft: clip((Δs_K^soft − Δs_K)/w_soft, 0, 1) # 𝟙_mono: 1 if nonincreasing I sequence else 0 # d_min : nearest-neighbor distance to 𝒞_sel (normalized coords) J_ws(θ) = h_ws(θ) − ωp · p_soft(θ) + ωm · 𝟙_mono(θ) + ωd · d_min(θ, 𝒞_sel)

Section 6 · Mechanism 2 of 2

Bounded weight-conditioned regional guidance: restarts, not replacements.

After the first six calls populate 𝒟, and only for t ≤ TL, we ask the LLM for a region — given the current decomposition weight, observed ranges, current best, and a compact state summary. The region is parsed, clipped, repaired, and accepted only if admissible. Its anchors join the numerical EI restarts; the original acquisition search is unchanged.

A · LLM does
Adds

Region anchors

  • Provide point, hyperrectangle, or "no preference"
  • Return is rejected if too narrow, too broad, or infeasible
  • Anchors live only inside the existing restart pool
  • "No preference" leaves the search untouched
B · LLM does not
Cannot

Modify the loop

  • Cannot replace the acquisition function
  • Cannot restrict the feasible search space
  • Cannot inject GP training targets or Pareto members
  • Cannot continue after t > TL
Why "weight-conditioned" The LLM prompt is conditioned on the active decomposition direction w⁽ᵗ⁾ and the BO state at iteration t. So the regional preference is a local look-ahead for the current trade-off — not a global, weight-independent prior.

Section 11 · What to take home

Where the LLM helps, where it doesn't, and what we explicitly leave out.

✓ Take
Three findings

What LLMBO-MO shows

  • A ParEGO backbone + battery-aware LLM warm start beats the same backbone with random init (+9.3% on Chen2020, +17.8% on Ecker2015).
  • The initialization carries the gain; regional guidance is a small, complementary refinement that tightens dispersion.
  • Simulator remains the only oracle — no LLM value enters 𝒟 or 𝒫 unevaluated.
! Boundary
What we don't claim

Scope, kept honest

  • All results are simulation-based; Dchg is a trajectory-averaged proxy, not a measured capacity-fade endpoint.
  • qEHVI / qNEHVI baselines not included — this is a backbone-matched comparison, not an exhaustive SOTA ranking.
  • Regional-guidance ablation uses three seeds; independent contribution is less firmly established than initialization.
  • Cross-LLM-backend and prompt-realization sweeps are out of scope; the prompt is fixed to V4-Flash.
