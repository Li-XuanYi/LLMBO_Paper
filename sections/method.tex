\section{Proposed LLMBO-MO}
\label{sec:method}

\subsection{Motivation}

The charging-design problem in \eqref{eq:cmop} is expensive because every new
protocol must be evaluated by the battery model before its objective values and
feasibility are known.
BO reduces the number of evaluations, but its surrogate is least informative at
the beginning of the search, when only a small initial design is available.
Battery-domain knowledge can help identify plausible regions at this stage, yet
LLM outputs are not equivalent to battery-model evaluations.
Treating generated objective values as observations would introduce unverified
evidence into GP fitting and Pareto comparison.

LLMBO-MO addresses this tension by assigning the two information sources
asymmetric roles.
The LLM provides \emph{search guidance}, whereas the battery simulator provides
\emph{optimization evidence}.
The primary mechanism is a knowledge-informed initial design whose protocols
are evaluated before entering the database.
An optional early advisory mechanism can additionally redirect acquisition
search, but it neither creates observations nor persists after simulator
evidence has accumulated.
Thus, objective values, feasibility, GP targets, and Pareto dominance remain
grounded exclusively in simulator-evaluated protocols.

\subsection{Framework}

The evidence flow of LLMBO-MO is shown in \autoref{fig:framework}.
Before sequential BO, the LLM generates protocol candidates from the problem
description and battery-domain heuristics.
The candidates are repaired to the protocol domain, screened for diversity,
combined with numerical initialization points, and evaluated by the battery
simulator.
Only these verified evaluations form the initial observation database $\bD$.

Sequential optimization then follows a numerical multiobjective BO backbone.
A weight vector defines the current trade-off direction; observed objectives
are transformed and scalarized; a GP surrogate and expected improvement (EI)
select the next protocol; and simulator evaluation updates $\bD$ and the Pareto
set $\bP$.
Within the first $T_{\mathrm L}$ iterations, an optional LLM advisory can supply
a validated point or region as an additional acquisition-search restart.
Invalid or absent advice falls back to ordinary EI, and after
$T_{\mathrm L}$ the numerical BO loop proceeds alone.
The bounded posterior-mean variant used only for component analysis is described
separately in Appendix~\ref{app:coupling}; it is not part of the principal
Chen2020 configuration.

\subsection{Main Steps}

\subsubsection{Knowledge-Informed Initialization}
\label{sec:warm_start}

The initialization mechanism targets the stage at which BO has the least
task-specific evidence.
Its prompt specifies the cell context, decision-variable bounds, $K$-stage
constant-current geometry, objective definitions, and qualitative charging
heuristics such as decreasing-current schedules and avoidance of extreme
terminal SOC spans.
The LLM returns a pool of numerical candidates and a self-reported score.
Non-numerical entries and duplicates are removed, non-finite values are
discarded, box violations are clipped, and candidates that cannot satisfy
$\Delta s_K\geq\Delta s_K^{\min}$ are rejected.
These operations check protocol-domain validity only; voltage and temperature
feasibility are still determined by the simulator.

Let $h_{\mathrm{ws}}(\btheta)\in[0,1]$ denote the LLM-reported score.
A soft penalty discourages a terminal SOC span below a preferred boundary:
\begin{equation}
p_{\mathrm{soft}}(\btheta)=
\operatorname{clip}\!\left(
\frac{\Delta s_K^{\mathrm{soft}}-\Delta s_K}{w_{\mathrm{soft}}},
0,1\right).
\label{eq:soft_penalty}
\end{equation}
Let $\mathbb I_{\mathrm{mono}}(\btheta)$ indicate a nonincreasing current
sequence.
The candidate portfolio is selected greedily according to
\begin{equation}
\begin{aligned}
J_{\mathrm{ws}}(\btheta)
={}&h_{\mathrm{ws}}(\btheta)
-\omega_p p_{\mathrm{soft}}(\btheta)
+\omega_m\mathbb I_{\mathrm{mono}}(\btheta)\\
&+\omega_d d_{\min}(\btheta,\mathcal C_{\mathrm{sel}}),
\end{aligned}
\label{eq:portfolio}
\end{equation}
where
\begin{equation}
d_{\min}(\btheta,\mathcal C_{\mathrm{sel}})=
\begin{cases}
0, & \mathcal C_{\mathrm{sel}}=\varnothing,\\
\displaystyle\min_{\mathbf c\in\mathcal C_{\mathrm{sel}}}
\|\widehat{\btheta}-\widehat{\mathbf c}\|_2,
& \text{otherwise}.
\end{cases}
\label{eq:diversity}
\end{equation}
The hat denotes normalized decision coordinates.
Random protocol-domain-valid points complete the initial design so that search
is not restricted to LLM proposals.
Most importantly, a candidate enters $\bD$ only after simulator evaluation.
The mechanism therefore changes the distribution of evaluated initial
locations without creating pseudo-observations.

\subsubsection{Numerical Multiobjective BO Backbone}
\label{sec:parego_backbone}

After initialization, LLMBO-MO uses a ParEGO-style numerical
backbone~\cite{ref4}.
Keeping the scalarization, GP model, and acquisition rule common to LLMBO-MO
and the primary BO baseline isolates the effect of the knowledge-informed
initial design.
Because the three objectives have different numerical ranges, charging time and
the degradation proxy are first logarithmically transformed:
\begin{equation}
\begin{aligned}
\tilde{\mathbf f}(\btheta)
&=[\ell_t(\btheta),\Delta T_p(\btheta),\ell_D(\btheta)]^\top,\\
\ell_t(\btheta)
&=\log_{10}\!\max(t_c/t_{\mathrm{ref}},\varepsilon_t),\\
\ell_D(\btheta)
&=\log_{10}\!\max(D_{\mathrm{chg}}/D_{\mathrm{ref}},
\varepsilon_D).
\end{aligned}
\label{eq:objective_transform}
\end{equation}
For objective $i$, let $R_{i,t}^{\mathrm{hist}}$ denote the observed range and
$R_i^{\mathrm{glob}}=\tilde y_i^{\mathrm{ref}}-
\tilde y_i^{\mathrm{ideal}}$.
The scale used by the implementation is
\begin{equation}
s_{i,t}=
\begin{cases}
R_i^{\mathrm{glob}},&
R_{i,t}^{\mathrm{hist}}<\rho_R R_i^{\mathrm{glob}},\\
R_{i,t}^{\mathrm{hist}},&\text{otherwise}.
\end{cases}
\label{eq:objective_scale}
\end{equation}
Using the global range when the early observed range is too narrow avoids
overemphasizing a poorly estimated scale.

At iteration $t$, a weight vector $\bw^{(t)}$ is selected from $\bW$, which is
initialized on a Das--Dennis simplex lattice and dispersed by projected
Riesz-energy relaxation~\cite{ref15}.
The transformed objectives are combined through an augmented Tchebycheff
function:
\begin{equation}
\begin{aligned}
\bar f_{i,t}(\btheta)
&=\frac{|\tilde f_i(\btheta)-\tilde z_{i,t}^{\ast}|}{s_{i,t}},\\
g_t(\btheta\mid\bw^{(t)})
&=\max_i w_i^{(t)}\bar f_{i,t}(\btheta)
+\rho_{\mathrm{aug}}\sum_{i=1}^{m}
w_i^{(t)}\bar f_{i,t}(\btheta),
\end{aligned}
\label{eq:tchebycheff}
\end{equation}
where $\bw^{(t)}\geq\mathbf 0$, $\mathbf1^\top\bw^{(t)}=1$, and $m=3$.
Feasible observations are re-scalarized by \eqref{eq:tchebycheff} at every
iteration.

An ARD Mat\'ern-$5/2$ GP with a white-noise term is fitted to standardized
scalar targets on normalized decision variables.
Kernel hyperparameters are estimated by marginal likelihood with multiple
restarts.
Let $\mu_t(\btheta)$ and $\sigma_t(\btheta)$ be its posterior mean and standard
deviation.
For minimization, EI is
\begin{equation}
\begin{aligned}
z_t(\btheta)
&=\frac{g_t^{\min}-\mu_t(\btheta)}{\sigma_t(\btheta)},\\
\mathrm{EI}_t(\btheta)
&=(g_t^{\min}-\mu_t(\btheta))\Phi(z_t)
+\sigma_t(\btheta)\phi(z_t),
\end{aligned}
\label{eq:ei}
\end{equation}
where $g_t^{\min}$ is the best observed scalar value and $\Phi(\cdot)$ and
$\phi(\cdot)$ are the standard normal cumulative distribution and density
functions.
The candidate pool contains the incumbent, Gaussian and uniform samples, and
multi-start L-BFGS-B solutions.
Every selected candidate is repaired to $\Theta_{\mathrm{proto}}$, evaluated by
the battery simulator, and appended to $\bD$; the feasible set and $\bP$ are
then updated.

\subsubsection{Optional Early Advisory Guidance}
\label{sec:region_pref}

Regional guidance is retained as a bounded auxiliary extension for the early
search window $t\leq T_{\mathrm L}$.
At iteration $t$, the prompt contains the current weight vector, observed
objective ranges, current best values, selected evaluated protocols, and a
summary of optimization progress.
The LLM can return a point, a hyperrectangular region, or an explicit
no-preference response, allowing it to abstain when the available context does
not support a useful recommendation.

A returned point or region is parsed, clipped, repaired to
$\Theta_{\mathrm{proto}}$, and validated.
A point preference is converted to a local hyperrectangle with fixed-width
margins; regions that are too narrow or too broad are rejected.
Anchors sampled from an accepted region are added only as restarts for numerical
EI maximization.
Consequently, advice can change where the acquisition optimizer searches but
cannot change an objective value or enter the GP training set.
Invalid advice falls back to the original candidate pool, and all advisory
interaction stops after $T_{\mathrm L}$.
The component evidence in Section~\ref{sec:component} does not establish a
systematic independent benefit from this extension, so it is not treated as a
co-equal source of the reported gain.

All paths therefore return to the same evidence chain: candidate selection,
simulator evaluation, database update, and Pareto update.
Algorithm~\ref{alg:llmbo} summarizes the principal procedure.

\begin{algorithm}[!t]
\caption{LLMBO-MO}
\label{alg:llmbo}
\footnotesize
\begin{algorithmic}[1]
\Require Simulator $\bS$, LLM $\bL$, total budget $N$, initial budget $n_0$,
weights $\bW$, optional guidance horizon $T_{\mathrm L}$
\Ensure Evaluated nondominated set $\bP$
\State Query $\bL$ for a warm-start pool; repair and rank by
\eqref{eq:portfolio}
\State Add selected LLM proposals and random protocol-domain-valid points
\State Evaluate $n_0$ initial protocols and initialize $\bD$
\For{$t=1$ to $N-n_0$}
    \State Select $\bw^{(t)}$ and re-scalarize feasible data by
    \eqref{eq:tchebycheff}
    \State Fit the GP surrogate and construct EI by \eqref{eq:ei}
    \If{optional guidance is enabled and $t\leq T_{\mathrm L}$}
        \State Query $\bL$; add a valid region only as EI-search restarts
    \EndIf
    \State Maximize EI and select $\btheta_{t+1}$
    \State Evaluate $\bS(\btheta_{t+1})$ and append the result to $\bD$
    \State Update the feasible set and Pareto archive $\bP$
\EndFor
\State \Return $\bP$
\end{algorithmic}
\end{algorithm}
